  TODOs and assumptions

  UML problems
  1. record_user_transaction has four parameters all named user, which won't
     compile. I used (code, username, user_type, credit).
  2. User::owns_game(user) takes a parameter called user, but it only makes
     sense as a game name, so it checks the collection for that name.
  3. User::add_game(game) only gets a name, so the price is 0.0 and the seller
     is empty.
  4. Session::find_user returns a copy as the UML says. It returns an
     empty-username User when nothing matches, and changes to the copy don't
     reach all_users.
  5. Account_Management holds the Session by reference, not by value. A copy
     would not see changes to the live user list.

  Behaviour the UML doesn't specify
  6. Session::login ignores pw, because User has no password.
  7. Session::process_transactions only prints a message. Session holds no
  Funds, Game_Transactions or Account_Management objects to dispatch commands
  to.
  8. Session::logout records code 00.
  9. Game_Transactions::buy and sell prompt on stdin. They don't check credit or
  ownership and don't update any user, because they have no User access. buy
  removes the game from the for-sale list.
  10. Account_Management is admin-only, using type "AA". create_user prompts for
  the type and starts credit at 0, and its code is 01. delete_user uses code 02
  and doesn't remove the user's games for sale.
  11. Funds::add_credit prompts for the amount and uses code 06. It doesn't
  update balances, and the user type is left blank because Funds can't see it.
  refund only records the refund and doesn't change balances.

  File formats
  12. Transaction_Writer uses fixed-width lines such as CC UUUUUUUUUUUUUUU TT
  CCCCCCCCC. Codes are 03 sell, 04 buy and 05 refund. Money is zero-padded with
  two decimals.
  13. write_file rewrites the whole log after every record, so the file is
  always current.
  14. Readers assumes fixed-width input files, with column positions marked in
  comments in Readers.cpp. User accounts are username type credit, available
  games are name seller price, and the game collection is name owner. An END
  line is skipped in the user accounts file.
  15. parse_money returns 0.0 for anything that isn't a number.
  16. Game_Transactions and Readers use default file names. Because the files
  read from the current directory, adjust those names and the column widths to
  your real file formats.
