  Ambiguities for your test plan

  1. Invalid user type: nothing says what happens if the type is misspelled or
     given as a code like FS. There's no error message for it and no test covers
     it.
  2. Whitespace in usernames: it isn't defined whether a username of only spaces
     is "empty", or whether leading and trailing spaces are trimmed or counted
     in the length.

     contain, or whether it can include spaces. A space inside a name would make
     the fixed-width transaction file hard to parse.

     as a duplicate of fullstduser1.

     the same session counts as a duplicate, or only users already in the
     accounts file.

     truncated to 15.
  7. Using a new account: it's unspecified whether a newly created user can log
     in before the back end processes the day's transactions.
